# dsh-group-vector-memory

给 DSH 群聊加一份按发言人隔离的记忆。每次群消息进入会话时，插件只在宿主确认的当前群内，召回这位发言人最近说过的话和语义相关的历史记录，并把结果注入当前回合。网页设置页可以浏览、编辑、删除和预览插件收录的消息。

## 适用环境

- 已在 DSH Web `0.2.2-rc.5` 验证。该版本要求 Node.js `24.9.0` 及以上，插件使用内置 `node:sqlite`。
- [dsh-im](https://github.com/xmanrui/dsh-im) 提供群消息归档和当前群授权。
- 可选的 OpenAI 兼容 Embeddings 服务。默认模型为 `BAAI/bge-m3`，向量维度为 1024。

## 安装

从 GitHub 克隆到运行 DSH 的主机。

```bash
git clone https://github.com/huajiao1998/dsh-group-vector-memory.git
```

在 DSH Web 打开「插件 → 添加插件」，填入克隆目录的绝对路径。安装后确认插件已启用，按插件管理页的状态提示操作。

## 首次使用

1. 确认 dsh-im 已在当前 DSH 环境接收并归档目标群的消息。在对应机器人的「上下文增强」设置中开启群聊增强并保留发言人 ID。
2. 打开「设置 → 群聊记忆 → 插件设置」，确认「启用群聊记忆」已开启。工作区范围留空时适用于所有工作区。
3. 在「向量模型」保存接口地址、模型名和服务所需的 API Key，再点「测试连接」。开启向量化后，待向量化的群消息文本和语义查询会发送给所配置的服务。只想使用本地近期记录和关键词时，关闭「允许向配置的向量服务发送文本」。
4. 切到「群聊记录」，点「立即同步」，展开目标群和成员，确认历史已收录。再让该成员在群里 @ 机器人并附上正文，检查同一回合是否出现记忆上下文。

## 查询群聊原文

在「设置 → 群聊记忆 → 原文查询」中选群，按发言人、关键词和日期筛选。AI 可以用 `group_chat_history` 查询宿主授权的当前群，同样支持这些筛选。

```js
group_chat_history({ keyword: '换模型', speaker: 'self', from: '2026-11-01', to: '2026-11-21', limit: 10 })
```

日期按 DSH 的本地时区，开始和结束日期均包含当天。`speaker: 'self'` 查机器人发出的消息，`speaker: 'others'` 查收到的消息，省略则查全部。结果按时间从新到旧，带 `nextCursor` 时可沿用筛选条件继续翻页。

QQ 群里 @ 机器人并收到已归档的 AI 回复后，插件会从 dsh-im 增量同步。有待处理的记忆消息时，在同步入库后生成向量。手动同步可到「群聊记录」点「立即同步」。自动触发依赖支持回复完成事件的 dsh-im 接入端。首次同步的范围取决于源归档当时保留的记录。

## 会话召回

自动注入和 `group_memory_lookup` 只查 DSH 宿主授权的当前群。模型不能通过参数切换群。私聊、网页消息、混合来源或无法唯一确认群的请求不会触发召回。群身份校验依赖 dsh-im 当前轮的群归档工具及默认归档位置。使用独立归档路径或关闭消息来源增强时，管理页仍可能可用，但会话注入和当前群授权可能无法工作。

```js
group_memory_lookup({ person: '示例群友', query: '服务器', limit: 5 })
```

`person` 支持名称或 ID。省略 `query` 时返回近期发言。语义查询最多等待 500 毫秒，向量服务不可用时仍会使用本地关键词和近期记录。此隔离约束插件的召回，不会改写 DSH 已写入的会话历史。需要彻底隔离历史上下文时，请为不同群使用独立 DSH 会话。

### QQ 的 @ 行为

- QQ 消息带正文时，按原发言人收录。消息进入会话后照常参与召回。启用向量服务时，正文也会向量化。
- 无正文、无附件的 QQ 纯 @ 在收录时跳过。旧库中的空白和纯 @ 记录会排除在召回和向量覆盖统计之外。原始归档由 dsh-im 管理。
- 补发一个纯 @ 来唤起前文，需要额外的 dsh-im 接入补丁。该补丁在同群、同一发言人 3 分钟内选择最近的正文，最多带上前两条作上下文。记忆插件以最后一条正文做召回。找不到合适的前文时会提示重发。本文的安装步骤只安装群记忆插件。

## 设置与管理

在「设置 → 群聊记忆」中：

- 总开关同时控制收录、外部向量化和会话记忆。关闭后不会删除已有数据。
- 工作区范围只限制会话注入和查询，不改变群历史收录范围。保存后，已有会话也会应用新范围。
- 「测试连接」使用已保存的配置发送一条固定测试文本，并显示接口返回的维度和耗时。
- 保存向量模型配置后，点「立即重建向量」可在后台分批补算缺失的向量。页面显示当前配置下符合向量化条件的记录及其覆盖进度。失败后可以继续，已覆盖的记录会保留。
- 群聊记录页可以翻页、编辑、删除或预览某个群友在当前群里的记忆。预览不填查询时只读近期发言，不会默认把历史消息发送给向量服务。
- 清除某个群友时，以确认操作时的消息源截止点为界，只清除其在该群的既有记忆，包括尚未同步的旧消息。之后新收到的消息仍可收录。消息源不可用或无法确定范围时，整人清除会报错，不执行部分删除。

## 配置示例

日常设置可在网页保存。默认配置文件为 DSH Home 下的 `plugins/dsh-group-vector-memory/config.json`。

```json
{
  "enabled": true,
  "workspaces": [],
  "embedding": {
    "enabled": true,
    "baseUrl": "https://api.siliconflow.cn/v1",
    "model": "BAAI/bge-m3",
    "dimensions": 1024,
    "apiKey": "sk-…"
  },
  "recall": {
    "recent": 6,
    "semantic": 8,
    "minScore": 0.25
  },
  "inject": {
    "enabled": true,
    "maxChars": 2000
  }
}
```

服务端配置保存 API Key，设置页仅显示掩码。变更向量服务的协议、域名或端口时，需要重新填写或清除已保存的密钥。接口、模型或维度变化后，插件使用独立的向量覆盖统计，可通过重建加快填充。

## 数据与升级

插件以只读方式读取 dsh-im 的群归档，并把副本保存在自己的 SQLite 数据库中。管理页的编辑和删除只影响插件副本。单条编辑会使旧向量失效，单条删除会留下删除标记，避免后续同步重新导入。

同步按接收时间及来源行号推进。旧版只有发送时间游标时，升级后会回放现存源归档，并保留已有记录、编辑和删除标记。来源没有持久的全局单调序号，源时钟倒退或数据库被外部替换时不提供顺序保证。来源归档已经清理、且插件未曾收录的消息无法补录。
